⚙️ Características da Camada de Internet

Responsável pela entrega de datagramas entre hosts distintos
Atua nos sistemas finais e nos roteadores
PDU (Protocol Data Unit): Pacote ou Datagrama

🎯 Função Principal:

Repassar segmentos da origem para o destino
Encapsula segmentos em datagramas (remetente)
Extrai segmentos de datagramas (receptor)

🔄 Processo de Encapsulamento:

Camada de Transporte (Segmento)
⬇️ Encapsulamento
Camada de Internet (Datagrama/Pacote)
⬇️ Encapsulamento
Camada de Acesso à Rede (Quadro)

⚠️ Serviço Não Confiável

Não garante que datagramas sejam entregues com sucesso
Não garante que cheguem na ordem correta
Paradigma de "melhor esforço"

🚀 Melhor Esforço (Best Effort):

Tenta realizar a entrega com o melhor aproveitamento possível
Pacotes só são descartados em condições especiais:
Escassez de recursos (buffer cheio)
Erros de transmissão
TTL expirado

🛡️ Onde fica a confiabilidade?

A confiabilidade deve ser fornecida por protocolos de camadas superiores, como o TCP na camada de transporte.

📡 Serviço Sem Conexão

Não existe comunicação prévia entre participantes
Origem monta o datagrama e adiciona endereçamento
Cada datagrama é tratado individualmente
Datagramas podem seguir caminhos diferentes

🗺️ Roteamento Passo-a-Passo (Hop-by-Hop):

1. Se origem e destino estão na mesma rede: envio direto
2. Se estão em redes diferentes: envio para próximo roteador
3. Processo se repete até alcançar a rede de destino
4. Cada roteador consulta sua tabela de roteamento

🔄 Resultado

Datagramas podem chegar fora de ordem
Cabe à camada superior reorganizar se necessário

🔧 Protocolos da Camada de Internet

📌 IP (Internet Protocol)

Protocolo principal da camada
Entrega de datagramas não confiável
Define formato do datagrama
Executa função de roteamento

📋 ICMP

Internet Control Message Protocol
Mensagens de erro e controle
Sinaliza situações anormais
Usado pelo comando PING

👥 IGMP

Internet Group Management Protocol
Entrega multicast
Múltiplos destinatários

🔍 ARP

Address Resolution Protocol
Resolve endereços IP em MAC
Necessário para envio na rede local

🎯 Todos trabalham juntos

Para prover o serviço completo de entrega de datagramas e roteamento

📦 Formato do Datagrama IP

|Ver|HLEN|Tipo Serviço| Comprimento Total |
| Identificador |Flags|Deslocamento Frag.|
|Tempo Vida|Protocolo| Cabeçalho Checksum|
| Endereço IP de Origem |
| Endereço IP de Destino |
| Opções IP (se houver) |Padding|
| Dados |

🔑 Campos Principais:

Version: Versão do IP (4 ou 6)
HLEN: Tamanho do cabeçalho
Total Length: Tamanho total
TTL: Tempo de vida

📍 Endereçamento:

Source IP: IP de origem
Destination IP: IP de destino
Protocol: Protocolo encapsulado
1=ICMP, 6=TCP, 17=UDP

⏱️ TTL e Fragmentação

⏰ Time To Live (TTL)

Número máximo de roteadores
Valor inicial definido pela origem
Cada roteador decrementa em 1
TTL = 0: datagrama descartado

🎯 Finalidade do TTL:

Evitar que datagramas circulem infinitamente na rede devido a loops de roteamento

✂️ Fragmentação

MTU (Maximum Transmission Unit)
Cada rede tem limite de tamanho
Datagramas grandes são fragmentados
Remontagem só no destino final

🔧 Campos de Controle:

Identification: ID do datagrama
Flags: Controle de fragmentação
Fragment Offset: Posição do fragmento

📍 Classes de Endereços IPv4

Classe Primeiro Octeto Bits de Rede Bits de Host Máscara Padrão
A 1-126 8 24 255.0.0.0 (/8)
B 128-191 16 16 255.255.0.0 (/16)
C 192-223 24 8 255.255.255.0 (/24)

🌐 Exemplos:

Classe A: 10.0.0.1
Classe B: 172.16.0.1
Classe C: 192.168.1.1

📊 Capacidade:

Classe A: 16,7 milhões de hosts
Classe B: 65.534 hosts
Classe C: 254 hosts

🌍 IPs Públicos vs IPs Privados

🌐 IPs Públicos

Válidos na Internet global
Atribuídos por entidades centralizadoras
IANA → RIRs → ISPs → Usuários
Únicos mundialmente

🏢 Exemplos de IPs Públicos:

8.8.8.8 (Google DNS)
1.1.1.1 (Cloudflare DNS)

🏠 IPs Privados

Não roteáveis na Internet
Uso em redes locais
Podem ser reutilizados
Definidos na RFC 1918

📋 Faixas Privadas:

10.0.0.0/8 (Classe A)
172.16.0.0/12 (Classe B)
192.168.0.0/16 (Classe C)

🔄 NAT (Network Address Translation)

Permite que redes privadas acessem a Internet através de um IP público

🕸️ Sub-redes (Subnetting)

Divisão de uma rede grande em redes menores
Melhor aproveitamento do espaço de endereços
Maior eficiência e organização

📊 Exemplo de Subnetting:

Rede original: 192.168.1.0/24 (256 endereços)


Dividindo em 4 sub-redes:

192.168.1.0/26 (64 endereços)
192.168.1.64/26 (64 endereços)
192.168.1.128/26 (64 endereços)
192.168.1.192/26 (64 endereços)

🎯 Máscara de Sub-rede:

Define quantos bits são para rede e quantos para hosts
255.255.255.192 = /26

⚙️ Processamento de Datagramas

📤 No Remetente:

1. Recebe segmento da camada superior
2. Adiciona cabeçalho IP
3. Define endereços origem/destino
4. Calcula rota (consulta tabela)
5. Fragmenta se necessário
6. Envia para camada inferior

📥 No Receptor:

1. Recebe datagrama da camada inferior
2. Verifica se é destinatário
3. Remonta fragmentos se necessário
4. Remove cabeçalho IP
5. Identifica protocolo superior
6. Entrega para camada apropriada

🔀 No Roteador Intermediário:

Consulta tabela de roteamento, decrementa TTL,
e encaminha para o próximo salto (next-hop)
